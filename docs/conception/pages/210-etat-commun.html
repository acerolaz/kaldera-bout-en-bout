2.4🧠 L'état commun d'une demande

Un objet typé par demande, EtatDemande. Les agents ne le modifient jamais directement : ils proposent un patch, l'orchestrateur le contrôle (fusionner), puis applique la transition. Le champ contrat de l'état porte la provenance du contrat ; ses termes restent dans demande.contrat.

class ContratDemande(BaseModel):   # ConfigDict(frozen=True) · écrite par l'orchestrateur seul
    """Provenance des termes du contrat ; les termes restent dans demande."""
    statut_extraction: Literal["valide", "non_exploitable"] = "valide"
    violations: tuple[str, ...] = ()
    source: Literal["extraction_vlm", "demande_json"] = "demande_json"
    modele: str | None = None
    version_prompt: str | None = None
    sha256: str | None = None
# niveau 1 : demande_niveau_1() fusionne gestion + termes extraits (3 verrous, 2.4 quater)
#           + provenance dans demande["contrat"] ; T0 lit contrat.statut_extraction

🔁 Invariance niveau 0 / niveau 1

Niveau 0 : provenance absente ⇒ source = "demande_json", statut_extraction = "valide" par construction ⇒ les 28 scénarios fournis passent sans changement. Niveau 1 : mêmes champs, remplis par l'extraction VLM.

Où vit-il ?

En mémoire ; avec une base, snapshot après chaque transition dans PostgreSQL (demandes.etat jsonb, 2.6), fiche finale dans demandes.fiche.

Pas d'écrasement

Propriété par section vérifiée à chaque écriture ; 1 état par demande ⇒ pas de verrou.

Données sensibles

Identité, texte libre, PDF et n° de contrat 🔒 ne sortent jamais vers 🕵️ antifraude ni vers un LLM.
