class ConfigLLM(BaseModel):
    fournisseur: Literal["azure"] = "azure"
    modele: str                     # nom de déploiement Foundry
    delai_agent_s: float = 1.2;  jetons_max: int = 3000;  tours_max: int = 3
    temperature: float = 0.0;    vision: bool = False

class ConfigAgents(BaseSettings):   # env_prefix="KALDERA_", délimiteur "__"
    pieces / estimation / antifraude / decision / relance: ConfigLLM | None
    azure_ai_chat_endpoint: str | None   # AZURE_AI_CHAT_ENDPOINT
    azure_ai_chat_key: SecretStr | None  # AZURE_AI_CHAT_KEY
class ConfigIngestion(BaseSettings): # env_prefix="KALDERA_INGESTION__"
    vlm: ConfigLLM | None;  delai_analyse_s = 60.0;  taille_max_mo = 10

def fabrique_llm(cfg, nom) -> ClientLLM | None:
    if config manquante or endpoint/clé absents: return None
    return AzureLLM.depuis(config, endpoint, cle)  # ChatCompletionsClient

🧾 Tracé pour l'audit

Chaque étape de la trace porte modele et version_prompt ; métriques par agent et par modèle. Chaque analyse VLM aussi (cache (sha256, modele, version_prompt)).

🔌 Un point d'accès, des modèles au choix

Tous les modèles passent par l'endpoint d'inférence Azure AI Foundry ; chaque agent peut y prendre un déploiement différent. Un autre fournisseur = un nouvel adaptateur de ClientLLM, sans toucher aux agents. Secrets dans le .env.

Noms de modèles = exemples. Le choix final se fait par la mesure (make eval, 4.4), consigné au journal. En attendant, .env.example propose Kimi-K2.6 pour les agents et gpt-4.1 pour le VLM ; sans clé, tout tourne en repli.
