5🎯 Choix tranchés et points ouverts

Les choix tranchés de la conception, tels que le code les applique, et ce qui a changé depuis le 8 octobre. Les points ouverts suivent.

#Choix tranché
1🏆 Machine à états finis déterministe, classe Orchestrateur explicite (option A) — sans LLM
2🔧 Éligibilité = tool is_eligible() ; 4 agents LLM ; 1 section → 1 écrivain ; aucun appel direct entre agents
3💶 Plafond appliqué par l'estimation, après la franchise
4🕵️ F1–F4 calculés par antifraude ; types de pièces exigés vérifiés par pieces
5⚡ L'état antifraude n'est jamais atteint si la demande est déjà conclue
6🧠 État Pydantic, patchs contrôlés, propriété par section, etat_courant
7🔐 Projection 7 champs + validation 4 couches → 1 appel réservé, 0 relance — dans la référence d'antifraude, avant le LLM
8🛑 Bornes = gardes : 12 étapes · 8 s · 1 relance · partenaire 3 s ; terminaison prouvée sur le graphe
9🤖 Chaque agent a son LLM, modèle lu dans le .env ; prompt de rôle, outils exclusifs, 2 à 3 tours
10🧱 Règles en outils ; le LLM rédige, la référence décide : champs décisifs = référence, sinon repli déterministe
11⏱️ Budget dégressif par agent ; 3 s A2A et 1 s décision réservées
12🔌 Port ClientLLM : Azure AI Foundry (ChatCompletionsClient) seul fournisseur réel, FakeLLM en test
13🛟 Filet de sécurité = exécution durable (filet + snapshot + reaper, ces deux derniers avec la base)
14📎 Pièces = références derrière DepotPieces ; relance n°k = dépôt n°k du type manquant
15🛡️ Garde-fou de sortie par agent ; decision : issue et file = appliquer_regles_s10, violation ⇒ repli
16🏭 Fabrique d'agents : table SPECS + creer_agent(), sans hiérarchie de classes
17📥 Ingestion hors équipe : fichier lu une fois, au dépôt ; VLM = outil, pas agent
18📜 Contrat PDF source de vérité, sous 3 verrous (schéma, barème, couche texte)
19🚪 Soumission + contrôle d'admission + garde T0 : jamais d'éligibilité sur des données non validées
20🐘 PostgreSQL facultatif : bytea, snapshots jsonb, registre à clé unique, file SKIP LOCKED
21💾 Cache d'analyse (sha256, modele, version_prompt) = reproductibilité
22🏭 Générateur déterministe (--seed 42) + manifeste = vérité terrain de l'éval du VLM
23🧵 Exécution synchrone : LLM, VLM et A2A sous délai par thread ; traiter_lot en threads
24🔁 Disjoncteur LLM : > 50 % de replis sur 60 s (≥ 10 tentatives) ⇒ repli des 4 agents, sans appel
25🧑 Espace assuré : vue projetée en liste blanche ; agent de relance borné aux pièces, hors machine
26📏 Mesurer pour de vrai : make epreuve (EX-01 → EX-06, T1–T11) et make eval (agent × modèle)

🔄 Évolutions depuis la version du 8 octobre

Chantier 2 : liaison A2A, monitorage, LLM réel, espace assuré. Lignes 23 à 26 du tableau (fond vert) ajoutées.

1Un seul fournisseur : Azure AI Foundry via azure-ai-inference, pour les agents et le VLM ; plus d'adaptateur par fournisseur.
2Rôle du LLM borné : chaque agent calcule d'abord sa référence déterministe ; le LLM rédige le texte de sa section, sans changer l'issue ni l'appel au partenaire.
3Exécution synchrone sous délai par thread ; seuls le cycle de vie de l'API et le flux SSE sont async.
4Persistance facultative : sans KALDERA_DATABASE_URL, ni snapshot ni reaper, registre A2A en mémoire.
5Disjoncteur LLM (EX-D33), un par orchestrateur ; nouvelle cause de repli disjoncteur.
6Espace assuré (UI1) : front React, API /assure/*, flux SSE, vue projetée ; un 5ᵉ agent LLM, la relance.
7A2A conforme au contrat v2.0 : Agent Card lue au démarrage, URL de même origine, nature de chaque appel tracée.
8Mesure réelle : make epreuve (référence archivée, verte) et make eval, qui attend encore les clés Azure.
