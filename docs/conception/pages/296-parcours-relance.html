💬 Agent de relance (relance.py)

  • Même mécanique qu'AgentLLM : le code calcule les faits (pièces attendues, intention de la question) ; le LLM ne rédige que le texte.
  • Outils : reference_relance (fait foi), liste_pieces, consigne_depot.
  • Entrée : la question est une donnée non fiable, chevrons neutralisés ; le LLM ne voit que la question, les pièces et l'identité (pour le seul contrôle de fuite).
  • Garde-fou : 600 caractères au plus, aucune pièce hors liste, aucun terme interdit (fraude, partenaire, argent, décision, état interne…).
  • Repli : gabarit de l'intention (liste, rejet, conseiller), jamais signalé.

Messages spontanés

Après une analyse (pièce à refaire) ou quand la liste devient complète, le worker publie un gabarit : aucun LLM dans ce chemin.

Le chat s'arrête au verdict

Une fois le verdict affiché, la page ne propose plus ni le chat ni le dépôt ; la route des messages répond 409 avant tout appel au LLM.

Éprouvé de bout en bout

make front-e2e (Playwright) : connexion, facture illisible, message spontané, question, nouveau dépôt, soumission, verdict, sans appel Azure.
